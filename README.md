# vibecheck

Проверка запросов к Agent API «Вайб-Маркетолог» по их же каталогу — до отправки и до списания денег.

Написано как демонстрация к [предложениям по API](docs/predlozheniya.md). Инструмент делает снаружи то, что предлагается сделать внутри платформы, и на реальных данных показывает, сколько случаев сегодня проходят молча.

## Зачем

`GET /capabilities` публикует по каждой модели допустимые значения, диапазоны и взаимоисключения. Сервер их не применяет. Проверено на живом API 28.07.2026:

| Запрос | Что объявлено в каталоге | Что делает сервер |
|---|---|---|
| `seedance-2`, `resolution: "4k"` | `480p / 720p / 1080p` | принимает, `valid: true` |
| `seedance-2`, `duration: 30` | `4-15s` | принимает (общий предел для всех видеомоделей — 60) |
| `z-image`, `aspect_ratio: "99:1"` | значения не объявлены | принимает |

Ошибки нет, возврата нет — сбоя ведь не было. Клиент платит 1188 ₽ и получает молча испорченный результат. Для автономного агента это худший вид отказа: у человека есть глаз, чтобы заметить, что ролик не той длины, у агента — нет.

## Как устроено

**Валидатор не знает ни одной модели.** Ни одного `if model == "seedance-2"` в коде нет. Все правила берутся из каталога, который платформа отдаёт наружу: список значений → проверка вхождения, диапазон → проверка границ, группы полей → проверка совместности сценариев. Новая модель в каталоге — новые правила без единой правки кода.

Именно поэтому такое решение и предлагается платформе: подключение новинок «в первые дни после релиза» — их конкурентное преимущество, и валидация не должна его тормозить.

## Запуск

```bash
pip install truststore          # опционально, см. «Про сертификаты»

# проверить тело запроса
echo '{"type":"video","model":"seedance-2","prompt":"город","resolution":"4k","duration":30}' > body.json
python vibecheck.py validate body.json
```

```
замечаний: 2 — запрос отправлять нельзя
  [enum_violation] resolution: «4k» вне допустимых: 480p, 720p, 1080p
  [range_violation] duration: 30 вне диапазона 4–15
```

```bash
# сверить два публичных описания между собой (токен не нужен)
python vibecheck.py audit

# добавить сверку с бесплатной сметой по всем моделям (нужен токен, денег не тратит)
python vibecheck.py audit --with-estimate
```

Токен берётся из `SPA_ACCESS_TOKEN` в окружении или из `.env`. Каталог по умолчанию тянется из API; чтобы работать офлайн — `VIBE_CATALOG=fixtures/capabilities.json`.

## Что находит сверка

На данных от 28.07.2026 — **25 расхождений** между `/capabilities` и `/prices`, притом что оба публичны и оба поданы как источник правды:

- 5 моделей есть в каталоге, но цены в прайсе нет (`seedream-5-pro`, `motion-control-720p/1080p`, …) — бюджет по ним посчитать нельзя, хотя `motion-control-720p` стоит 450 ₽;
- 10 моделей есть в прайсе, но их нет в каталоге (`grok-ttv-10`, `resize-2k`, `suno-voice-create`, …) — параметры узнать неоткуда;
- у 9 моделей **разный тип**: `gemini-omni-character` — `image` в каталоге и `text` в прайсе, `seedance-2` — `video` и `other`. Поле `type` обязательно в `/generate`, а категории `other` там не существует;
- тип `text` объявлен в `capabilities.types`, но моделей этого типа в каталоге нет ни одной.

Сверка со сметой добавляет расхождения цен: `gpt-image-1.5` — 20 ₽ в каталоге против 19 ₽ в смете, `el-tts-turbo` — 29 ₽ против 6 ₽ (29 ₽ это флет, отменённый вашей же документацией 16.07).

## Тесты

```bash
python test_vibecheck.py      # или pytest
```

14 тестов, офлайн, на сохранённом каталоге. Шесть из них — случаи из группы «сервер это принимает и оплачивает»; остальные проверяют, что валидатор не ругается на корректные запросы, в том числе на минимальный корректный запрос к каждой из 45 моделей каталога.

## Границы

- **Семантика `mutually_exclusive` выведена, а не прочитана.** Документация это поле не описывает. Из подсказок в каталоге следует, что группы — взаимоисключающие сценарии: внутри группы поля совместимы (`first_frame_url` + `last_frame_url`), между группами — нет. Если трактовка неверна, правится одна функция.
- **Правила, которые есть только в тексте, не проверяются.** Например, «`web_search` работает только без исходных материалов и иначе отбрасывается» живёт в подсказке модели прозой. Такие правила стоит перенести в машинную часть каталога — тогда валидатор подхватит их сам.
- **Цена считается по каталогу и не учитывает ступенчатых тарифов.** `grok-ttv` — 36 ₽ для ролика до 5 секунд, 196 ₽ для десяти, 316 ₽ для пятнадцати; в каталоге лежит только 36. Точную цену даёт `/generate/estimate`, валидатор её не подменяет.
- **Проверяются параметры, а не смысл.** Что `prompt` уместен, а `image_urls` ведёт на нужную картинку, инструмент не знает.

## Про сертификаты

На Windows Python из некоторых дистрибутивов падает на `CERTIFICATE_VERIFY_FAILED: certificate has expired` — протух бандл корневых сертификатов внутри дистрибутива, сертификат сайта при этом валиден. `truststore` переключает проверку на системное хранилище и снимает проблему; если пакета нет, код работает на бандле по умолчанию. Для `curl` тот же случай лечится флагом `--ssl-no-revoke`.
