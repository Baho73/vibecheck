# Разбор Agent API «Вайб-Маркетолог»

Работа по тестовому заданию: изучить платформу и предложить что-то полезное для её API.

Получилось четыре вещи: ревью публичного API с находками, предложения по их устранению, идеи для развития продукта и работающий инструмент, который одну из находок закрывает снаружи.

Всё проверено на живом API 28.07.2026. Около 60 запросов, из них платный один: генерация за 1,2 ₽.

---

## С чего начать

Если есть десять минут, читайте [ревью](docs/api-review.md), раздел P1. Там четыре находки, каждая с командой для воспроизведения.

Если есть тридцать, добавьте [предложения](docs/predlozheniya.md): что с этими находками делать и в каком порядке.

Если интересно не про API, а про продукт, идите сразу в [идеи развития](docs/idei-razvitiya.md).

## Что в каких файлах

### [docs/api-review.md](docs/api-review.md) · ревью API

Что нашлось и чем это подтверждается. Сначала то, что сделано сильно, потом находки по цене ошибки для клиента: четыре критичных, девять сбивающих с толку, три мелочи. В конце приложение с командами, которыми всё воспроизводится.

Главная находка: каталог публикует ограничения, которые не применяются. Запрос `resolution: "4k"` при объявленном перечне `480p/720p/1080p` проходит смету и уходит в оплату.

### [docs/predlozheniya.md](docs/predlozheniya.md) · что с этим делать

Пять предложений по API и одно по позиционированию продукта, от самого дешёвого во внедрении к самому крупному:

1. Каталог, который проверяет сам себя.
2. Права ключа в ответе `/me`.
3. Единый формат ошибок без исключений.
4. Смета на сценарий и бюджет задачи вместо суточного лимита.
5. Версия контракта по требованию.
6. Позиционирование: от списка моделей к списку работ, рецепты как первоклассная сущность.

### [docs/idei-razvitiya.md](docs/idei-razvitiya.md) · идеи для роста

Шесть идей не про починку, а про то, что можно продавать и чего сейчас не продаётся. Черновик перед чистовиком, продажа результата вместо попытки, пресеты из накопленной статистики, продажа агентам через MCP, регулярность без подписки, счётчик сэкономленного. У каждой идеи указано, чем она рискует.

### [docs/vibecheck.md](docs/vibecheck.md) · описание инструмента

Как запускать, что находит, где границы применимости. Читать, если хотите прогнать проверку у себя.

### [docs/razvedka-api.md](docs/razvedka-api.md) · протокол проверки

Черновой журнал: какие запросы отправлялись, что отвечал сервер, какие гипотезы не подтвердились. Нужен, если хотите проверить не выводы, а сами измерения. Там же список того, что осталось непроверенным и почему.

## Что можно запустить прямо сейчас

```bash
# найдёт запрос, который сервер принял бы и списал 1188 ₽
echo '{"type":"video","model":"seedance-2","prompt":"город","resolution":"4k","duration":30}' > body.json
python vibecheck.py validate body.json

# сверит каталог с прайсом, токен не нужен
python vibecheck.py audit

# тесты
python test_vibecheck.py
```

Валидатор не знает ни одной модели: все правила берутся из вашего же каталога. Новая модель в каталоге даёт новые правила без правки кода. Это и есть предложение 1, показанное в работе.

## Границы

Проверялся публичный контур снаружи. Кода платформы я не видел. Партнёрский контур, то есть Директ, автопилот и мост в Битрикс24, закрыт соглашением и по обычному ключу недоступен. Вебхуки, а также поведение при 403 и 429, не проверял.

Про продукт и позиционирование пишу как посторонний, посмотревший сайт. Данных о том, кто и как у вас покупает, у меня нет, поэтому там гипотезы, а не выводы.

Одну свою находку я по ходу снял: сначала записал, что каталог вводит в заблуждение ценой, потом убедился, что рядом с базовой ценой лежат `tier_prices`, `price_note` и `price_by_quality`, то есть каталог честен. История правки видна в коммитах.
