# Ревью публичного Agent API «Вайб-Маркетолог»

**Дата:** 28.07.2026 · **Автор:** Иван Пономарёв

**Объём проверки.** Публичный контур Agent API насчитывает 21 метод, из них я вызвал 13. Голосовой блок, загрузку медиа, safety-check и тестовую отправку вебхука не трогал. Плюс MCP-сервер, каталог моделей и прайс. Всего около 60 запросов, из них платный один: генерация `z-image` за 1,2 ₽. Все находки воспроизводятся командами из приложения.

**Чего я не видел.** Исходного кода. Партнёрского контура: Директ, автопилот и мост в Битрикс24 закрыты соглашением и по обычному ключу недоступны. Вебхуков, потому что для них нужен публичный приёмник. Поведения при 403 и 429.

---

## Резюме

API спроектирован лучше, чем большинство генеративных платформ, которые я интегрировал. Смета до списания, идемпотентность с различимыми исходами, подписанные ссылки на своём домене, MCP с корректными метаданными OAuth 2.1: зарубежные провайдеры доходят до такого не сразу.

Проблемы лежат не в фундаменте, а в зазоре между тем, что API объявляет, и тем, что он проверяет. Каталог публикует ограничения, которых валидатор не знает. Прайс расходится с каталогом. Страница возможностей описывает контур, которого у клиента с обычным ключом нет. Каждая находка ниже это место, где разработчик пишет код по документации и получает не то, что ожидал.

Разметил по цене ошибки для клиента. **P1** стоит денег или ломает интеграцию молча, таких четыре. **P2** сбивает с толку. **P3** мелочи.

---

## Что сделано сильно

Отмечаю не из вежливости: это то, что я бы при доработке не трогал.

**Смета лучшая часть API.** `POST /generate/estimate` возвращает не только цену, но и баланс после списания, суточный лимит с признаком `within_limit`, результат проверки каждого media-URL, список принятых полей `valid_params`, недостающие обязательные `required_missing`, отброшенные `rejected` и человеческие `warnings`. Бесплатно. Это делает возможным честный агентский цикл: посчитал, показал пользователю, списал.

**Идемпотентность доведена до конца.** Проверил живой генерацией: повтор с тем же ключом и телом вернул `replayed: true` без второго списания, тот же ключ с другим телом дал 409. Третий исход, параллельный дубль, заявлен в документации, но я его не воспроизводил. Большинство API останавливается на первом случае.

**Возврат заложен в контракт.** `auto_refund_on_error` объявлен в разделе `features` каталога, а `refunded` и `refund_amount` это поля первого класса в статусе генерации, а не строка в переписке с поддержкой. Сам возврат я не вызывал, потому что для этого нужен сбой у поставщика.

**Результат живёт на вашем домене.** `display_url` подписан, работает без логина, `expires_at` равен ровно семи дням, ссылок поставщика в ответе нет вообще. Это защищает и клиента, у которого ссылка не протухнет через час, и вас, потому что апстрим не виден.

**Discovery без токена.** `/capabilities`, `/prices`, `/health` и MCP `tools/list` открыты. Агент может изучить платформу до регистрации: правильное решение для времени, когда интеграцию пишет модель, а не человек.

**Ошибки в едином формате.** `status`, `error`, `message` по-русски, `details` с разбором по полям, `request_id`. С одним исключением, см. P1-4.

## P1: стоит денег или ломает интеграцию молча

### P1-1. Объявленные ограничения не применяются

Каталог публикует по каждой модели `enums`, `limits` и `mutually_exclusive`. Валидатор их не использует.

| Запрос | Что объявлено в `/capabilities` | Ответ сметы |
|---|---|---|
| `seedance-2`, `resolution: "4k"` | `enums.resolution = [480p, 720p, 1080p]` | `valid: true`, `rejected: []`, предупреждений нет |
| `seedance-2`, `duration: 30` | `limits.duration = "4-15s"` | принято; 422 приходит только на 99, по пределу 60 |
| `z-image`, `aspect_ratio: "99:1"` | значения не объявлены | `valid: true` |
| `seedance-2`, `first_frame_url` плюс `reference_image_urls` | объявлен `mutually_exclusive` | не отмечено; правило продублировано прозой в `hint` |

Предел 60 общий для всех видеомоделей, а не модельный. `strict=true` ловит незнакомые имена полей, но не запрещённые значения.

**Последствие.** Клиент отправляет `duration: 30` на модель с потолком 15 и платит 1188 ₽. Что дальше сделает поставщик, обрежет ролик или проигнорирует параметр, снаружи не видно: платную генерацию с заведомо неверной длительностью я не запускал. Видно другое: ошибки клиент не получает, а значит и возврата не будет, потому что формально сбоя не было. Для агента это худший вид отказа, потому что заметить подмену некому.

**Рекомендация.** Применять к телу запроса тот же каталог, который отдаётся наружу. Это одна проверка на входе `/generate` и `/estimate`, данные для неё уже собраны. Где ограничение известно только прозой, как `web_search` в подсказке `seedance-2`, перенести его в машинную часть. Где не известно, лучше не публиковать `enums` вовсе, чтобы не обещать проверку, которой нет.

### P1-2. Прайс расходится с каталогом и со сметой

Прогнал бесплатную смету по всем 45 моделям каталога и сверил с обоими описаниями:

| Модель | Смета | Каталог | `/prices` |
|---|---|---|---|
| `motion-control-720p` | 450 ₽ | формула `ceil(min(max(video_duration,3),30)) * 15` | нет |
| `motion-control-1080p` | 660 ₽ | формула | нет |
| `seedream-5-pro` | 40 ₽ | 40 ₽ плюс `price_by_quality` | нет |
| `el-tts-turbo` (100 знаков) | 6 ₽ | 29 ₽ | 29 ₽ |
| `gpt-image-1.5` | 19 ₽ | 20 ₽ | 20 ₽ |

Каталог здесь точнее прайса. Цена есть у всех 45 моделей, у двух через формулу, и там, где она зависит от параметров, каталог честно помечает это через `price_note`, `tier_prices` и `price_by_quality`. А вот `/prices` не содержит пяти моделей вовсе и показывает `el-tts-turbo` по флету 29 ₽, который ваша документация упразднила 16.07.

**Последствие.** Документация советует: «`GET /prices` отдаёт цены всех моделей, жёстко зашивать их в код не нужно». Разработчик следует совету и получает смещённую смету, а пяти моделей не видит совсем. На пакетной задаче ошибка накапливается.

**Рекомендация.** Собирать `/prices` из того же места, откуда цену берёт смета, и ронять сборку, если модель есть в каталоге, а в прайсе её нет.

### P1-3. `GET /me` не показывает права ключа

Метод отдаёт имя, префикс токена, срок годности, суточный лимит, счётчики запросов и даты. Нет ни списка прав, ни `allowed_ips`, ни статуса Яндекс-OAuth, хотя документация обещает «лимиты, остатки, статус Яндекс OAuth», а сама модель прав заявлена как явная и закрытая по умолчанию.

**Последствие.** Права выданы явно, и это правильно. Но агент не может узнать свои права иначе, чем отправив вызов и получив 403. Остаётся либо пробовать вслепую, либо зашить предположение о правах в конфиг, то есть ровно то, от чего разграничение прав и защищает.

Побочно: у ключа есть срок годности, у моего 90 дней, поле `expires_at` в ответе есть. В документации об этом не сказано. Интеграция, поставленная в работу и не следящая за этим полем, однажды встанет без объяснения.

**Рекомендация.** Добавить в `/me` список выданных прав и, если он задан, список разрешённых адресов. Это отображение существующих данных. И упомянуть срок жизни ключа в разделе про аутентификацию.

### P1-4. Ответ 409 нарушает единый формат ошибок

Документация обещает: `status` и `request_id` есть всегда, по `status` можно ветвиться, не заглядывая в код ответа. Ответ на конфликт ключа идемпотентности приходит без обоих:

```json
{"error":"idempotency_key_conflict",
 "message":"This idempotency_key was already used with a DIFFERENT request body…",
 "generation_id":25714}
```

Для сравнения, 422 на `duration` приходит с полным набором полей, включая `details` и `request_id`.

**Последствие.** Клиент, написанный по документации через `if resp["status"] == "error"`, на этом ответе либо падает, либо принимает отказ за успех. Идемпотентность нужна для повторов, то есть срабатывает как раз тогда, когда у клиента уже что-то пошло не так.

**Рекомендация.** Привести 409 к общей схеме и проверить остальные коды одним прогоном. Единый формат ценен только при полном покрытии.

## P2: сбивает с толку, но денег напрямую не стоит

**P2-1. Каталог и прайс описывают разные множества моделей.** Пять моделей есть в каталоге, но не в прайсе. Десять есть в прайсе, но не в каталоге: `grok-ttv-10/20/30`, `grok-itv-*`, `resize-2k/4k`, `seedream-5-lite-edit`, `suno-voice-create`. У девяти моделей разный тип: `gemini-omni-character` это `image` против `text`, `seedance-2` это `video` против `other`. Категории `other` в `/generate` не существует.

**P2-2. Заявленный `type: text` не имеет ни одной модели.** Он присутствует в `capabilities.types` и в перечислении MCP-схемы, но раздела `text` в `capabilities.models` нет.

**P2-3. Тип модели не проверяется.** `gemini-omni-character` принят и как `image`, и как `text`, обе сметы валидны, цена одна. Обязательное поле, значение которого ни с чем не сверяется. Похоже, поэтому расхождение P2-1 и не всплывает как явная ошибка. Но и поймать свою опечатку клиент не может.

**P2-4. Витрина обещает контур, которого у клиента нет.** Страница `/api` заявляет 58 эндпоинтов, раздел «Экосистема» говорит про 46, и показывает `GET /campaigns`, `POST /autopilot/run`, `GET /inbox` как карту возможностей. Публично доступен 21 метод, остальное требует партнёрского соглашения. В каталоге про это сказано прямо, ключ `partner_only` даже ссылается на ту же страницу. Рядом с перечнем эндпоинтов на самой странице я такой оговорки не нашёл, но мог просмотреть.

**P2-5. Список `endpoints` в каталоге неполон относительно самого себя.** В нём 16 методов. Соседний блок `getting_started.flow` велит звать `GET /me` и `GET /capabilities`, которых в списке нет. Отсутствует и `/health`, хотя он отвечает, и недокументированный `/usage`.

**P2-6. MCP отдаёт модели пустой контракт.** В схемах `generate_content` и `estimate_generation` параметры описаны как `"params": {"type": "object"}` без свойств. Claude или ChatGPT, подключив коннектор, не получают ни одного имени параметра и вынуждены сначала вытянуть каталог на 28 килобайт и вывести структуру из него. Схемы нет там, где модель её ищет, отсюда и повторяющаяся путаница `image_input`, `image_urls` и `first_frame_url`.

**P2-7. `/health` не сообщает о здоровье.** Отдаёт `{status: ok, api_version, time, recent_requests: null}`. Состояния поставщиков нет, хотя переключение на резерв и быстрый отказ при сбое поставщика заявлены как функции платформы. Агент не может узнать, что модель сейчас недоступна, иначе как получив ошибку на платном запросе.

**P2-8. Лимит частоты расходится с документацией.** В заголовках `X-RateLimit-Limit: 60`, и без токена, и с токеном, при документированных 120 запросах в минуту для права `read`. Заголовка `X-RateLimit-Reset` нет, поэтому корректный бэкофф написать не на чем.

**P2-9. `GET /usage` существует и нигде не описан.** Отдаёт период, сумму трат, число запросов и разбивку по дням. Разбивки по ключам нет.

## P3: мелочи

- **Тиры видеомоделей двоятся между описаниями.** У `grok-ttv` в каталоге есть `tier_prices` и `price_note`, который прямо велит сверяться со сметой, так что каталог тут корректен. Но сами тиры названы именами моделей `grok-ttv-10` и `grok-ttv-20`, которых в каталоге как записей нет, а в `/prices` они лежат самостоятельными строками. Вдобавок `grok-ttv-30` за 436 ₽ есть в прайсе, но отсутствует в `tier_prices` каталога, хотя документация помечает этот тир устаревшим.
- **`limits` записаны тремя способами в одном объекте:** `"duration": "4-15s"` это диапазон строкой, `"prompt_max": 20000` это максимум длины значения, `"reference_image_urls": 9` это максимум числа элементов. Различить можно только по имени поля, из-за чего разбор требует списка известных полей-списков.
- **`hint` написан по-английски**, тогда как сообщения об ошибках приходят по-русски. Для правил, которые существуют только в подсказке, это лишний барьер.

## Что бы я чинил первым

Порядок по отношению цены ошибки к объёму работы, а не по величине задачи.

1. **P1-4, формат 409.** Правка на несколько строк, убирает падение клиента в момент повтора.
2. **P1-3, права в `/me`.** Отображение уже существующих данных, снимает необходимость угадывать.
3. **P1-2, прайс.** Сверка двух источников, ловится одним тестом в сборке.
4. **P1-1, применение ограничений.** Самая большая из четырёх и единственная, где клиент сейчас платит за молчаливо испорченный результат.

P2-6, схема в MCP, стоит отдельно: это не починка, а рост. Сейчас коннектор работает вопреки отсутствию контракта, за счёт того, что модели умные. С типизированными параметрами шанс попасть с первого раза заметно выше, и каталог не придётся держать в контексте целиком.

## Приложение: как воспроизвести

На Windows для `curl` нужен флаг `--ssl-no-revoke`, иначе schannel рвёт соединение с ошибкой `CRYPT_E_NO_REVOCATION_CHECK`. Питоновский `urllib` в некоторых дистрибутивах падает на просроченном бандле корневых сертификатов, сертификат сайта при этом валиден; лечится пакетом `truststore`.

```bash
B=https://lk.vibemarketolog.ru/api/agent
H="Authorization: Bearer $SPA_ACCESS_TOKEN"

# P1-1: значение вне объявленного перечня принимается
curl -s --ssl-no-revoke -X POST -H "$H" -H "Content-Type: application/json" \
  -d '{"type":"video","model":"seedance-2","prompt":"test","resolution":"4k"}' \
  $B/generate/estimate

# P1-2: цена модели, которой нет в прайсе
curl -s --ssl-no-revoke -X POST -H "$H" -H "Content-Type: application/json" \
  -d '{"type":"video","model":"motion-control-720p","prompt":"test"}' \
  $B/generate/estimate        # estimated_cost_rub: 450
curl -s --ssl-no-revoke $B/prices | grep motion-control   # пусто

# P1-3: права ключа в ответе отсутствуют
curl -s --ssl-no-revoke -H "$H" $B/me

# P1-4: 409 без status и request_id
# повторить /generate с тем же idempotency_key и другим prompt
```

Сверка каталога, прайса и сметы по всем 45 моделям автоматизирована:

```bash
python vibecheck.py audit                    # каталог против прайса, без токена
python vibecheck.py audit --with-estimate    # плюс сверка со сметой, пара минут
```
