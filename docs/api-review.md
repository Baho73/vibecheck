# Ревью публичного Agent API «Вайб-Маркетолог»

**Дата:** 28.07.2026 · **Автор:** Иван Пономарёв
**Объём проверки:** публичный контур Agent API (21 метод), MCP-сервер, каталог моделей, прайс.
**Метод:** 60+ запросов, из них платный один (генерация `z-image` за 1,2 ₽). Все находки воспроизводятся командами из приложения.
**Чего я не видел:** исходного кода, партнёрского контура (Директ, автопилот, Битрикс24 — закрыты соглашением), вебхуков (нужен публичный приёмник), поведения при 403 и 429.

---

## Резюме

API спроектирован лучше, чем большинство генеративных платформ, которые я интегрировал. Смета до списания, идемпотентность с тремя различимыми исходами, возврат при сбое, подписанные ссылки на своём домене, MCP с полноценным OAuth 2.1 — это уровень, до которого зарубежные провайдеры доходят на третий год.

Проблемы лежат не в фундаменте, а в **зазоре между тем, что API объявляет, и тем, что он проверяет**. Каталог публикует ограничения, которых валидатор не знает; прайс и каталог расходятся; страница возможностей описывает контур, которого у клиента нет. Каждая находка ниже — это место, где добросовестный разработчик написал код по документации и получил не то, что ожидал.

Приоритет один: **P1 — стоит клиенту денег или ломает интеграцию молча.** Их четыре.

---

## Что сделано сильно

Отмечаю не из вежливости — это то, что при доработке трогать нельзя.

**Смета — лучшая часть API.** `POST /generate/estimate` возвращает не только цену, но и баланс после списания, суточный лимит с флагом `within_limit`, результат HEAD-проверки каждого media-URL, список принятых полей `valid_params`, недостающие обязательные `required_missing`, отброшенные `rejected` и человеческие `warnings`. Бесплатно. Это делает возможным честный агентский цикл «посчитал → показал пользователю → списал».

**Идемпотентность доведена до конца.** Проверил живой генерацией: повтор с тем же ключом и телом → `replayed: true` без второго списания; тот же ключ с другим телом → 409; параллельный дубль → отдельный код. Большинство API останавливается на первом случае.

**Деньги возвращаются сами.** `refunded` и `refund_amount` — поля первого класса в статусе, а не строка в поддержку.

**Результат живёт на их домене.** `display_url` подписан, работает без логина, `expires_at` ровно +7 дней, ссылок провайдера в ответе нет вообще. Это защищает и клиента (ссылка не протухнет через час), и их (апстрим не виден).

**Discovery без токена.** `/capabilities`, `/prices`, `/health` и MCP `tools/list` открыты. Агент может изучить платформу до регистрации — правильное решение для эпохи, когда интеграцию пишет модель, а не человек.

**Ошибки в едином формате** — `status`, `error`, `message` по-русски, `details`, `request_id`. С одним исключением, см. P1-4.

## P1 — стоит денег или ломает интеграцию молча

### P1-1. Объявленные ограничения не применяются

Каталог публикует по каждой модели `enums`, `limits` и `mutually_exclusive`. Валидатор их не использует.

| Запрос | Что объявлено в `/capabilities` | Ответ сметы |
|---|---|---|
| `seedance-2`, `resolution: "4k"` | `enums.resolution = [480p, 720p, 1080p]` | `valid: true`, `rejected: []`, предупреждений нет |
| `seedance-2`, `duration: 30` | `limits.duration = "4-15s"` | принято; 422 приходит только на 99 — «не должно быть больше 60» |
| `z-image`, `aspect_ratio: "99:1"` | enums не опубликованы вовсе | `valid: true` |
| `seedance-2`, `first_frame_url` + `reference_image_urls` | `mutually_exclusive` объявлен | не отмечено; правило продублировано прозой в `hint` |

Предел 60 — общий для всех видеомоделей, а не модельный. `strict=true` ловит только незнакомые **имена** полей, но не запрещённые **значения**.

**Последствие.** Клиент отправляет `duration: 30` на модель с потолком 15, платит 1188 ₽ и получает ролик не той длины — либо обрезанный провайдером, либо с игнорированным параметром. Ошибки нет, возврата нет (сбоя ведь не было). Для агента это худший вид отказа: молчаливый.

**Рекомендация.** Применять к телу запроса тот же каталог, который отдаётся наружу — это одна проверка на входе `/generate` и `/estimate`, данные для неё уже есть. Где ограничение известно только прозой (`hint`), перенести его в машинную часть; где не известно — не публиковать `enums`, чтобы не обещать проверку, которой нет.

### P1-2. Прайс расходится с реальной ценой

Смета по 45 моделям против `/prices` и `price` в каталоге:

| Модель | Смета | Каталог | Прайс |
|---|---|---|---|
| `motion-control-720p` | **450 ₽** | нет | **нет** |
| `motion-control-1080p` | **660 ₽** | нет | **нет** |
| `el-tts-turbo` (100 знаков) | 6 ₽ | 29 ₽ | 29 ₽ |
| `gpt-image-1.5` | 19 ₽ | 20 ₽ | 20 ₽ |

`el-tts-turbo` за 29 ₽ — флет, который ваша же документация объявила отменённым 16.07 (реально 6 ₽ за начатую 1000 знаков). `motion-control-*` есть в каталоге, но в прайсе отсутствуют: клиент, планирующий бюджет по `/prices`, получит на них ноль вместо 450–660 ₽.

**Последствие.** Документация прямо советует: «`GET /prices` отдаёт цены всех моделей — жёстко зашивать их в код не нужно». Разработчик следует совету и получает смещённую смету. На пакетной задаче в тысячу единиц ошибка накапливается.

**Рекомендация.** Один источник цены. Проще всего — генерировать `/prices` из того же места, откуда цену берёт смета, и уронить сборку, если модель есть в каталоге, а цены нет.

### P1-3. `GET /me` не показывает права ключа

Отдаёт `name`, `token_prefix`, `expires_at`, `daily_spend_limit`, `daily_spend_today`, `requests_today`, `requests_total`, `last_used_at`, `created_at`. Нет `scopes`, нет `allowed_ips`, нет статуса Яндекс-OAuth — хотя документация обещает «лимиты, остатки, статус Яндекс OAuth», а сама модель прав заявлена как явная и fail-closed.

**Последствие.** Права выданы явно и это правильно — но агент не может узнать свои права иначе, чем отправив вызов и поймав 403. Для автономного агента это означает: либо пробовать вслепую, либо зашивать предположение о правах в конфиг — то есть ровно то, от чего скоупы и защищают.

Побочно: у ключа есть срок годности (мой — 90 дней, поле `expires_at` в `/me`). В документации об этом ни слова. Интеграция, поставленная на прод и не следящая за этим полем, однажды встанет.

**Рекомендация.** Добавить `scopes` и `allowed_ips` в `/me` — данные уже есть, это отображение. И упомянуть срок жизни ключа в разделе аутентификации.

### P1-4. Ответ 409 нарушает единый формат ошибок

Документация: `status` и `request_id` есть **всегда**, по `status` можно ветвиться, не заглядывая в HTTP-код. Реальный ответ на конфликт ключа идемпотентности:

```json
{"error":"idempotency_key_conflict",
 "message":"This idempotency_key was already used with a DIFFERENT request body…",
 "generation_id":25714}
```

Ни `status`, ни `request_id`. Для сравнения, 422 на `duration` приходит с полным набором.

**Последствие.** Клиент, написанный по документации (`if resp["status"] == "error"`), на этом ответе упадёт с промахом ключа или молча посчитает ответ успешным. Идемпотентность — механизм для ретраев, то есть срабатывает как раз в момент, когда клиенту уже плохо.

**Рекомендация.** Привести 409 к общей схеме. Заодно проверить остальные коды одним прогоном — единый формат ценен только при полном покрытии.

## P2 — сбивает с толку, но денег напрямую не стоит

**P2-1. Каталог и прайс описывают разные множества моделей.** 5 моделей есть в каталоге без цены; 10 есть в прайсе без каталога (`grok-ttv-10/20/30`, `grok-itv-*`, `resize-2k/4k`, `seedream-5-lite-edit`, `suno-voice-create`); у 9 моделей **разный тип** (`gemini-omni-character` — image против text, `seedance-2` — video против other). Категории `other` в `/generate` не существует. Оба эндпоинта публичны и оба поданы как источник правды.

**P2-2. Заявленный `type: text` не имеет ни одной модели.** Присутствует в `capabilities.types` и в enum MCP-схемы, но раздела `text` в `capabilities.models` нет.

**P2-3. Тип модели не проверяется.** `gemini-omni-character` принят и как `image`, и как `text` — обе сметы валидны, цена одна. Обязательное поле, значение которого ни с чем не сверяется. Это объясняет, почему расхождение P2-1 до сих пор никого не сломало, но убирает у клиента возможность поймать свою ошибку.

**P2-4. Витрина обещает контур, которого у клиента нет.** Страница `/api` заявляет 58 эндпоинтов (раздел «Экосистема» — 46) и показывает `GET /campaigns`, `POST /autopilot/run`, `GET /inbox` как карту возможностей. Публично доступен 21 метод; остальное — партнёрское соглашение, о чём честно сказано в `partner_only` внутри каталога, но не на странице. Разработчик узнаёт об этом после выпуска ключа.

**P2-5. Список `endpoints` в каталоге неполон относительно самого себя.** В нём 16 методов, при этом соседний блок `getting_started.flow` велит звать `GET /me`, `GET /balance`, `GET /capabilities` — их в списке нет. Нет и `/generations`, `/health`, хотя оба работают.

**P2-6. MCP отдаёт модели пустой контракт.** В схемах `generate_content` и `estimate_generation` параметры описаны как `"params": {"type": "object"}` без свойств. Claude или ChatGPT, подключив коннектор, не получают ни одного имени параметра — модель обязана сначала вытянуть каталог на 28 КБ и угадать структуру. Отсюда же растут задокументированные прозой грабли `image_input` против `image_urls` против `first_frame_url`: это не невнимательность интеграторов, это отсутствие схемы в том месте, где модель её ищет.

**P2-7. `/health` ничего не сообщает о здоровье.** Отдаёт `{status: ok, api_version, time, recent_requests: null}`. Состояния поставщиков нет, хотя переключение на резерв и «отказ сразу при сбое поставщика» заявлены как функции платформы. Агент не может узнать, что Veo сейчас лежит, иначе как получив ошибку на платном запросе.

**P2-8. Лимит частоты расходится с документацией.** В заголовках `X-RateLimit-Limit: 60` — и без токена, и с токеном, при документированных 120 rpm для права `read`. `X-RateLimit-Reset` отсутствует, поэтому корректный бэкофф написать нельзя.

**P2-9. `GET /usage` существует и нигде не описан.** Отдаёт `{period, total_spent, total_requests, by_day[]}`. Разбивки по ключам нет.

## P3 — мелочи

- **`price` в каталоге не отражает ступенчатую цену.** `grok-ttv.price = 36` — это цена ролика до 5 секунд; 10 секунд стоят 196 ₽, 15 — 316 ₽. Тарифы лежат в `tier_prices` под именами моделей, которых в каталоге нет. Цена честная, но клиент, умножающий `price` на количество роликов, ошибётся в пять раз.
- **`limits` записаны тремя способами в одном объекте:** `"duration": "4-15s"` (диапазон строкой), `"prompt_max": 20000` (максимум значения), `"reference_image_urls": 9` (максимум длины массива). Различить можно только по имени поля.
- **`hint` — по-английски**, тогда как `message` в ошибках по-русски. Для правил, которые существуют только в `hint`, это лишний барьер.
- **`X-RateLimit-Reset` отсутствует** (см. P2-8).

## Что бы я чинил первым

Порядок — по отношению «цена ошибки для клиента» к «объёму работы», а не по величине задачи.

1. **P1-4 (формат 409)** — правка на несколько строк, убирает падение клиента в момент ретрая.
2. **P1-3 (`scopes` в `/me`)** — отображение существующих данных, снимает необходимость угадывать права.
3. **P1-2 (прайс)** — сверка двух источников, ловится одним тестом в сборке.
4. **P1-1 (применение ограничений)** — самая большая из четырёх, но и единственная, где клиент сейчас платит за молчаливо испорченный результат.

P2-6 (схема в MCP) стоит отдельно: это не починка, а рост. Сейчас коннектор работает вопреки отсутствию контракта — за счёт того, что модели умные. С типизированными параметрами он начнёт работать с первого раза и без каталога в контексте.

## Приложение: как воспроизвести

На Windows нужен `--ssl-no-revoke` — иначе schannel рвёт соединение с `CRYPT_E_NO_REVOCATION_CHECK`. Питоновский `urllib` в дистрибутиве anaconda падает на просроченном бандле корневых сертификатов; сертификат сайта при этом валиден.

```bash
B=https://lk.vibemarketolog.ru/api/agent
H="Authorization: Bearer $SPA_ACCESS_TOKEN"

# P1-1: значение вне объявленного enum принимается
curl -s --ssl-no-revoke -X POST -H "$H" -H "Content-Type: application/json" \
  -d '{"type":"video","model":"seedance-2","prompt":"test","resolution":"4k"}' \
  $B/generate/estimate

# P1-2: цена модели, которой нет в прайсе
curl -s --ssl-no-revoke -X POST -H "$H" -H "Content-Type: application/json" \
  -d '{"type":"video","model":"motion-control-720p","prompt":"test"}' \
  $B/generate/estimate        # → estimated_cost_rub: 450
curl -s --ssl-no-revoke $B/prices | grep motion-control   # → пусто

# P1-3: права ключа в ответе отсутствуют
curl -s --ssl-no-revoke -H "$H" $B/me

# P1-4: 409 без status и request_id
# (повторить /generate с тем же idempotency_key и другим prompt)
```

Полный скрипт сверки каталога со сметой по всем 45 моделям — `probe.py` + `audit.py`, прогон занимает около минуты и не тратит денег.
