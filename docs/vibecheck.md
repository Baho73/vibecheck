# vibecheck: инструмент

Проверка запросов к Agent API «Вайб-Маркетолог» по их же каталогу, до отправки и до списания денег. Демонстрация к [предложению 1](predlozheniya.md).

## Зачем

`GET /capabilities` публикует по каждой модели допустимые значения, диапазоны и взаимоисключения. Сервер их не применяет. Проверено на живом API 28.07.2026:

| Запрос | Что объявлено в каталоге | Что делает сервер |
|---|---|---|
| `seedance-2`, `resolution: "4k"` | `480p / 720p / 1080p` | принимает, `valid: true` |
| `seedance-2`, `duration: 30` | `4-15s` | принимает; отказ приходит только на 99, по общему пределу 60 |
| `z-image`, `aspect_ratio: "99:1"` | значения не объявлены | принимает |

Первые два случая валидатор ловит. Третий поймать нельзя: каталог для `z-image` допустимых значений не публикует, поэтому проверять не с чем. Это чинится только на стороне платформы.

Смета оценивает такой запрос в 1188 ₽ и пропускает его в оплату. Платную генерацию с заведомо неверной длительностью я не запускал, поэтому не знаю, обрежет поставщик ролик или проигнорирует параметр. Знаю другое: ошибки клиент не получит, а значит и возврата не будет. Для автономного агента это худший вид отказа, потому что заметить подмену некому.

## Как устроено

Валидатор не знает ни одной модели. Ни одного `if model == "seedance-2"` в коде нет. Все правила берутся из каталога, который платформа отдаёт наружу: перечень значений даёт проверку вхождения, диапазон даёт проверку границ, группы полей дают проверку совместности сценариев. Новая модель в каталоге даёт новые правила без правки кода.

Поэтому я и предлагаю такое решение платформе: подключение новинок в первые дни после релиза это их преимущество, и валидация не должна его тормозить.

## Запуск

```bash
pip install truststore          # опционально, см. «Про сертификаты»

echo '{"type":"video","model":"seedance-2","prompt":"город","resolution":"4k","duration":30}' > body.json
python vibecheck.py validate body.json
```

```
замечаний: 2, запрос отправлять нельзя
  [enum_violation] resolution: «4k» вне допустимых: 480p, 720p, 1080p
  [range_violation] duration: 30 вне диапазона 4-15
```

```bash
python vibecheck.py audit                    # каталог против прайса, токен не нужен
python vibecheck.py audit --with-estimate    # плюс сверка со сметой, пара минут
```

Токен берётся из `SPA_ACCESS_TOKEN` в окружении или из `.env`. Каталог по умолчанию тянется из API; для работы офлайн задайте `VIBE_CATALOG=fixtures/capabilities.json`.

## Что находит сверка

На данных от 28.07.2026 сверка даёт 25 расхождений: 24 между каталогом и прайсом плюс одно внутри самого каталога. Оба описания публичны и оба поданы как источник правды.

- 5 моделей есть в каталоге, но в `/prices` их нет. Цена при этом известна: у `seedream-5-pro` это 40 ₽, у `motion-control-720p` она задана формулой `ceil(min(max(video_duration,3),30)) * 15 ₽`. Клиент, который планирует бюджет по прайсу, как советует документация, этих моделей не увидит.
- 10 моделей есть в прайсе, но их нет в каталоге: `grok-ttv-10`, `resize-2k`, `suno-voice-create` и другие. Параметры узнать неоткуда.
- У 9 моделей разный тип. `gemini-omni-character` числится как `image` в каталоге и как `text` в прайсе, `seedance-2` как `video` и `other`. Поле `type` обязательно в `/generate`, а категории `other` там не существует.
- Тип `text` объявлен в `capabilities.types`, но моделей этого типа в каталоге нет ни одной.

Сверка со сметой добавляет расхождения цен: `gpt-image-1.5` стоит 20 ₽ по каталогу и 19 ₽ по смете, `el-tts-turbo` 29 ₽ и 6 ₽. Второе значение это отменённый флет: документация упразднила его 16.07, реальная цена посимвольная.

## Тесты

```bash
python test_vibecheck.py      # или pytest
```

15 тестов, офлайн, на сохранённом каталоге. Четыре из них воспроизводят случаи, проверенные на живом API, где смета вернула `valid: true`. Ещё два случая, длина промпта и число элементов списка, проверены только против каталога. Остальные тесты защищают от ложных срабатываний, в том числе на минимальном корректном запросе к каждой из 45 моделей каталога.

## Границы

**Что проверялось.** Публичный контур снаружи. Кода платформы я не видел. Партнёрский контур, то есть Директ, автопилот и мост в Битрикс24, закрыт соглашением и недоступен по обычному ключу. Вебхуки, а также поведение при 403 и 429, я не проверял.

**Семантика `mutually_exclusive` выведена, а не прочитана.** Документация это поле не описывает. Из подсказок в каталоге следует, что группы задают взаимоисключающие сценарии: внутри группы поля совместимы, как `first_frame_url` с `last_frame_url`, а между группами нет. Если трактовка неверна, правится одна функция.

**Имена полей-списков заданы в коде.** Список `LIST_PARAMS` нужен, чтобы отличить «максимум 9 элементов» от «максимум значение 9»: в каталоге оба записаны одинаково, просто числом. Новое поле-список потребует одной строки.

**Правила, которые есть только в тексте, не проверяются.** Например, «`web_search` работает только без исходных материалов и иначе отбрасывается» живёт в подсказке модели прозой. Такие правила стоит перенести в машинную часть каталога, тогда валидатор подхватит их сам.

**Цена берётся из каталога и не пересчитывается.** Там, где каталог помечает цену как переменную через `tier_prices`, `price_by_quality` или `price_formula`, валидатор так и говорит и отправляет за точной цифрой в `/generate/estimate`. Подставлять базовую цену вместо итоговой он не станет.

**Проверяются параметры, а не смысл.** Уместен ли промпт и ведёт ли `image_urls` на нужную картинку, инструмент не знает.

## Про сертификаты

На Windows Python из некоторых дистрибутивов падает с ошибкой `CERTIFICATE_VERIFY_FAILED: certificate has expired`. Протух бандл корневых сертификатов внутри дистрибутива, сертификат сайта при этом валиден. `truststore` переключает проверку на системное хранилище и снимает проблему; если пакета нет, код работает на бандле по умолчанию. Для `curl` тот же случай лечится флагом `--ssl-no-revoke`.
